repo는 시나리오·소설·대본용 네이티브 집필 도구다. 작가는 글을 쓴다. 프로그램은 대사·상황·나레이션을 구분하고 인물과 등장 위치를 연결한다. 모든 작업은 키보드로 끝낸다.

01

제품 정의

작가가 서식과 데이터 관리를 신경 쓰지 않도록 한다.
PRINCIPLE 01

입력은 단순하게

입력용 문법은 짧다. 글쓰기 중 메뉴를 열 필요가 없다. 키보드에서 손을 떼지 않는다.

PRINCIPLE 02

인물은 자동 연결

처음 한 번만 [[김철수]]를 등록한다. 이후 같은 이름은 Rust 코어가 오브젝트에 자동 연결한다.

PRINCIPLE 03

원고는 복구 가능하게

원고를 TXT로 보존한다. 변경 기록을 SQLite에 남긴다. 종료 뒤에도 삭제 문장을 찾는다.

04

작성 문법

기호는 입력 명령이다. 내보낼 때는 기호를 제거하고 문단 서식을 적용한다.
SCENE / 장면# 병원 복도 - 밤

장면 단위로 인식한다. 장면 번호는 내부 ID로 유지한다.

DIALOGUE / 대사@@ 박영희는 어디 있어? @@

화자 아래로 들여쓰기한다. 입력 창에서도 구별한다.

DESCRIPTION / 상황·행동## 김철수가 문을 연다. ##

지문으로 분류한다. 필요 시 가운데 또는 왼쪽 정렬을 서식 템플릿에서 설정한다.

NARRATION / 나레이션₩₩ 그날 모든 것이 시작됐다. ₩₩

나레이션 서식을 적용한다. 소설 모드에서는 본문 문단으로 매핑할 수 있다.

OBJECT / 오브젝트 최초 등록[[김철수]] / [[장소:서울역]]

한 번 등록한 이름은 이후 평문 입력만으로 자동 연결한다.

NOTE / 출력 제외 메모// 이 장면의 감정선을 다시 검토한다.

프로젝트 안에는 남기고 최종 문서에서는 제외한다.

문법 정책: 원본은 UTF-8 그대로 저장한다. `₩`(U+20A9)과 한국어 키보드에서 보이는 백슬래시 문자의 입력 차이는 별도 회귀 시험으로 다룬다. 미리보기와 출력은 원본을 변경하지 않는다.

오브젝트 엔진

“오브젝트는 처음 한 번만 등록한다”를 시스템 규칙으로 구현한다.

등장 위치 기록

장면 17 / p.35

등장 횟수·대사 수·장면별 등장 목록을 관리한다.

Rust 기반 공통 코어(repo-core)를 단일 진실 공급원(Single Source of Truth)으로 삼아 파일 구조, 문법 파서, 인물 참조 ID, 한국어 조사(은/는/이/가) 처리, SQLite 스냅샷, 내보내기 규칙을 통합합니다. Windows(C++)와 macOS(Swift)는 C ABI 바인딩(repo_core.h)을 통해 동일한 정합성과 최고의 메모리 안정성을 보장받습니다.

프로젝트 디렉터리

MyStory/ ├─ project.json ← 기획: 버전·옵션 ├─ script/ │ ├─ main.txt ← 현재 지원 │ └─ scenes/ ← 확장 예정 ├─ project.sqlite ← 현재 지원 ├─ assets/ ← 향후 자료 └─ backups/ ← 복구 백업
기준 원고: UTF-8 TXT. 텍스트를 독점 DB에 가두지 않는다.
DATA

SQLite 공통 데이터

objects · aliases · mentions · revisions · project_meta. 이후 scenes · relations · operation_journal · migration_version을 확장한다.

SPEED · 목표

입력 응답

Rust 코어 기반 100만 자 원고 기준 입력 처리 p95 8ms 이내를 목표로 한다. 전체 재분석을 피하고 변경된 블록만 증분 파싱한다.

PORTABLE

단일 배포

Windows는 독립 실행 EXE 1개(Rust 정적 링크). macOS는 ZIP 해제 후 .app 1개로 실행한다. 별도 런타임이나 서버는 불필요하다.
